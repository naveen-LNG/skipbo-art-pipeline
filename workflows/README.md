# Saved workflows on the SkipBo ComfyUI server

Snapshot of everything under the server's `workflows/` folder, taken **2026-10-11** using GET requests only. Nothing on the server was changed.

- `originals/`: the raw UI-format JSON, byte for byte as the server holds it.
- `<name>.md`: generated per workflow, with the pipeline, every parameter, the prompts verbatim and the canvas notes.
- This README is the hand-written part: what each workflow is for and what is wrong with it.

To refresh after someone edits a workflow on the server:

```bash
python tools/comfy_snapshot.py --images --history
```

## Two engines, two prompt grammars

These workflows run on two very different models. A prompt written for one does not work on the other. This is the most important fact for the skill.

| | **Z-Image Turbo** (Icon, Cards, and all 433 of Claude's character jobs) | **Nano Banana Pro** (LR, LS, ArtStyle, NanoBananaTest) |
|---|---|---|
| What it is | A 6B diffusion model with a Qwen3-4B text encoder, running locally on the T4 | Gemini 3 Pro Image, a reasoning LLM that draws, called as an API from the server |
| Settings in use | 8 steps, `cfg 1.0`, `res_multistep`/`simple`, shift 3, negative = `ConditioningZeroOut` | temperature 0.5–1.0, 1K–4K, aspect set per workflow |
| Reads instructions? | **No.** It encodes text as a description of the picture. "no X", "NOT X" and "--avoid X" all *add* X | **Yes.** It follows structured instructions, negations, numbered checklists and "IMAGE 1 / IMAGE 2" roles |
| Uses reference images? | Only as img2img/inpaint latents (`denoise` decides how much survives) | Natively, up to 6 images per call, and it understands the role of each |
| Cost per image | ~100 s of T4 time, no API cost | Gemini API cost per call; slower; cannot be re-seeded deterministically |
| Best for | Fast, cheap iterations; inpainting fixes on an approved master | Style transfer, faithful edits, multi-reference consistency, scene composition |

## Per-workflow notes

### SKIPBO - LR render: the best-structured prompt on the server
- About 3,500 words in two parts. Everything from `MEDIUM` to `LENS AND PERSPECTIVE` is a **reusable house-style block** (no outlines, two-zone soft shading plus one highlight, flat colour divisions, three theme colours given in HSB, a three-band depth layout, 9:16 safe areas for the UI). Everything from `SCENE:` down describes this one image (the autumn carousel).
- **Reuse:** the skill should keep the style block as a fixed file and only ever write the scene block. That removes the largest source of drift: rewriting style wording on every request.
- **Watch:** `SAFE AREAS` is stated twice (once in the style block, once in the scene block, with slightly different wording). If they ever disagree the model has to pick one, so keep one copy only.
- Temperature 1.0 is high for a style-locked render. The human sessions in the history used 0.35–0.6 for faithful edits.

### SKIPBO - LS sketch
- The same two-part pattern: a pencil-style block (`MEDIUM`, `LINE`, `LINE WEIGHT`, `FORM AND SHADING`, `DETAIL ECONOMY`, `AVOID`), then `SUBJECT`, `ANATOMY`, `COMPOSITION`, `BACKGROUND`, `PROPS`, `LETTERING` for the image itself.
- The `ANATOMY` line (five digits, four toes, no visible teeth) is a good habit: it states the count up front instead of fixing it afterwards.

### ArtStyle: a prompt that has piled up revisions
- About 2,900 words, and much of it is history ("rejected three times", "the last attempt broke it…"). Nano Banana reads every sentence as an instruction, so leftover history turns into **conflicting instructions**:
  - `RENDER STYLE - FLAT TOY-LIKE VECTOR` vs `DO NOT PRODUCE A FLAT-COLOUR VECTOR LOOK`.
  - "smooth soft gradients" vs "The surfaces stay flat" vs final check "Every surface FLAT colour".
  - "Keep IMAGE 1's layout" vs "NO OUTLINES — you must depart from IMAGE 1 here".
- **Bug:** the prompt has a full section titled `IMAGE 2 IS A RENDER-QUALITY REFERENCE`, but only `image_1` is connected. There is no image 2, so the model is told to match a reference it never receives.
- **Fix pattern:** after each round, rewrite the brief as a clean description of the target. Never add another "the last attempt…" paragraph.

### NanoBananaTest
- A short, clean, two-image template: `image_1 = LAYOUT REFERENCE`, `image_2 = ART STYLE REFERENCE ONLY`. Naming each image's role explicitly is the right pattern and the skill should use it everywhere.
- The output line packs exclusions together ("no characters, no people, no text, no UI"). That's fine for Nano Banana but would backfire on Z-Image.

### Icon - Skip-Bo
- The house icon style is defined in two `Note` nodes (`Prompt 1` adds a fixed 45° 2.5D "collectible" camera; `Prompt 2` is front-facing). The active `CLIPTextEncode` is the subject (*Honey Dew Mushroom Pot…*) followed by `Prompt 1`.
- **It's on Z-Image at cfg 1, so the negatives backfire.** `--avoid realistic 3D rendering, excessive blur, photorealism, harsh lighting, deep black shadows…` is Midjourney syntax. Z-Image has no `--avoid`. Those words are encoded as positive conditioning and push the image *toward* realism, blur and black shadows. `(NOT realistic 3D)`, `no sharp angles` and `avoiding pure black` do the same.
- Other parts are good and should be kept: the 3–5 chunky elements, hue-shifted shadows, coloured outlines rather than black, the long-lens near-orthographic 45° view.

### Cards - Skip-Bo -Test
- A Z-Image + Disney LoRA (`DisneyIZT` trigger word) test. The prompt asks for a 3D Disney-Pixar look, which **conflicts with the 2D painted house style** used everywhere else. Treat it as an experiment, not a style source.
- The same problem appears: "No text on the image" and "without any blur" are sent as positive conditioning.
- It's roughly 600 words of prose, most of it audience marketing ("For an audience of women aged 35+…"). A diffusion text encoder gets nothing from that, and it dilutes the visual tokens.

## What was actually used (history, 8–11 Oct)

From [`../references/usage-reports/job-history-2026-10-08_to_2026-10-11.jsonl`](../references/usage-reports/job-history-2026-10-08_to_2026-10-11.jsonl), all 615 jobs the server still holds:

- 433 Z-Image Turbo jobs (none used a LoRA), 174 `easy imageRemBg` cut-outs (RMBG-1.4) and 8 Nano Banana Pro jobs (human sessions doing recolours, flat-colour passes and the sketch pass).
- The Z-Image jobs break down as 83 text-to-image, 49 img2img (all at denoise < 1) and **301 masked inpaints** (`SetLatentNoiseMask`, 211 of them at denoise 1.0). Most of the character work was inpainting one patch at a time (an eye, a mouth, an arm) on a master image. At denoise 1.0 the patch is redrawn from text plus the surrounding pixels only, which explains why the snout and muzzle drift from patch to patch (see the contact sheet in `comfyui_image_summary.html`).
- The saved workflows above were **not** what Claude ran. It built its own API graphs. That's why the house style blocks in LR/LS never reached the character work.
