# Rulings made during implementation

Decisions taken without stopping to ask, each with what it costs if wrong. Copied from the SDD ledger when the branch finished (2026-10-13).

- run tasks in parallel along the DAG in separate git worktrees, contrary to the skill's one-at-a-time rule — user explicitly asked for DAG parallelism — cost if wrong: merge conflicts, handled at merge time.
- T4 starts after T1 merges (not in wave 1) — its test needs rig_annotations.load — cost: a short delay.
- T6 golden = the committed experiments rig JSONs (fox and moose), no tests/golden copy — HEAD already reproduces them byte-identically — cost: none; if experiments rigs change later, the golden moves with them (acceptable, they're the deliverable).
- rebuild commands for existing rigs (T5, T6): fox --master experiments/2026-10-11-fox-parts/fox_master.png --body experiments/2026-10-11-part-variants/fox/body --heads experiments/2026-10-11-fox-parts/fox-spine/face-heads --variants experiments/2026-10-11-part-variants/fox/variants --name fox; moose --master experiments/2026-10-11-moose-parts/moose-spine-v1/moose_master.png --body experiments/2026-10-11-part-variants/moose/body --heads experiments/2026-10-11-moose-parts/moose-spine-v1/face-heads --variants experiments/2026-10-11-part-variants/moose/variants --name moose.
- drafts vs gate — validate() must accept DRAFT pieces (status proposed) with role "" or missing required points (propose writes those), but a piece with status confirmed/fixed must pass every rule, and a master with status confirmed/fixed must have every MASTER_POINTS entry — spec: the file is the gate and propose creates partial drafts — cost if wrong: drafts with typos pass validation until confirmed (caught then).
- fingertip/thumb_tip only on hand pieces (and master fingertip_*) — spec lists fingertip/thumb_tip as hand points — cost: none.
- SNAP_RADIUS_FRAC = 0.6 x the piece's short side (spec said 0.15) — at 0.15 a limb end of radius ~0.5 x width can never be accepted (r <= 1.5 x radius) — cost if wrong: the search catches more outline; mitigated by the arc-coverage gate.
- snap_round_end gets a fit-quality gate: kept points must span >= 120 deg of arc and be >= 50% of the in-radius outline, else None (snap failed -> doubt) — reviewer showed confident wrong circles on cuffs/flat ends — cost: more failed snaps (doubts) on odd shapes.
- DEFAULT_KIND hand.wrist, forearm.wrist, leg.hem -> "opening" (not round_end) — these ends are painted flat/cuffed (fox hands, moose cuffs, leg hems); opening snap gives the edge centre + width, which is what placement needs — cost: none for round ones (opening centre ~ end centre after push-in).
- T7 render_worn_strip returns (path, [(name, ok)]) — the plan's test needs the labels — cost: none.
- T9 head/hat/tail/ears/antlers/props placed via match_parts on their rest output images; --body ignored with --annotations — cost: none.
- the worn strip draws every output with image-down along the stub (the verdict's convention), no fingertip alignment — picture, verdict and the image-down convention used for gestures must agree; the true in-rig thumb angle is measured later by QA thumb_dir — cost if wrong: strip slightly misstates thumbs on hands painted tilted; QA catches it.
- snap displacement guard — a snap that moves the point more than 0.10 x the piece's short side from `at` is rejected (snap = "failed", keep `at`, doubt) — the agent's rough point carries the meaning; snapping may refine, not relocate — cost: more doubts where rough points are sloppy.
- feet are NOT rotated by normalise (painted upright, like the master); only upperarm, forearm, leg and hand rotate — cost: a foot painted tilted stays tilted (visible at checkpoint).
- hands without a fingertip (fist, thumbsup) rotate by the wrist->centroid angle rounded to the nearest 90 deg; hands with a fingertip rotate exactly — cost: a fist painted at 30 deg stays at 30 deg (the placement aligns rest hands to the master anyway).
- also bleed nearest opaque colour into alpha-0 pixels within 4 px (alpha unchanged) — the real Spine runtime samples straight-alpha textures bilinearly, so hidden colour can fringe there even though Pillow (premultiplied) doesn't show it — cost: none (pixels invisible at alpha 0).
- annotation mode matches tails/ears/antlers/horns over -90..90° in 10° steps (refined ±5° around the best) — tails are painted sideways and not normalised — cost: slower build (a few pieces).
- annotation mode keeps the "drop separate ears when the expression heads include them" rule — otherwise the fox's ears double — cost: none.
- report.json "parts" in annotation mode lists each placed part with method ("two_point"/"matcher"/"socket"), stretch, narrow — cost: none.
- T8b fix task — rig_snap.search_radius uses the piece's own width across its principal axis (axis_ends width) instead of the image-box short side; displacement guard follows it; plus T8 minors (leftover tilt > 30° → doubt, rest-hand fallback → doubt, document rotated sign, reject empty/path-y character) — tilted real limbs (fox raised sleeves 25-45°) would otherwise all fail round-end snaps — cost: one small task.
- add piece status "ignored" (unused pieces on a sheet, e.g. spare tails/sleeves): validate accepts it with any/empty role, normalise skips it, unconfirmed/doubts exclude it, confirm leaves it — real sheets carry extras and confirm must not be blocked by them — cost: an accidentally ignored piece is silently absent (visible in the overlay label).
- check's doubts exclude role-less drafts (already listed in unconfirmed) — T10 review noise — cost: none.
- thumb direction = the component of (thumb_tip - wrist) PERPENDICULAR to the hand's axis (wrist->fingertip, else image-down for joint-end-up outputs). rig_hands gains thumb_vector(wrist, thumb_tip, fingertip=None); normalise's mirror rule, the worn verdict, and QA thumb_dir all use it — wrist->thumb on real hands runs mostly along the forearm (fox point: 27° vs 90° target), so mirrors were coin-flips — cost: none; synthetic results unchanged in sign.
- a failed snap on a piece with confidence >= 0.7 is NOT a doubt question; it stays visible (red label in the overlay) and is listed under "snap_failed" in check's JSON. Doubts stay for low confidence, ambiguous mirror, facing mismatch, leftover tilt, missing master thumb_side — spec said failed snap -> doubt; real art fails most round-end snaps (domed, skewed ends) and would flood ~15 questions per sheet — cost if wrong: a badly placed rough point on a confident piece is only caught by eye in the overlay or by rig QA.
